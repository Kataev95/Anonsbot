# 🍬 IRISKA 3.0 — бот-анонс

Отдельный репозиторий: **основной iriska-bot не изменён**. При старте отправляет в группу **интерактивное HTML-сообщение** с 10-дневным обратным отсчётом и анимацией 🐱🦊🐰🐲, затем закрепляет сообщение, если есть соответствующее право. После успешной публикации процесс остаётся запущенным, но Telegram больше не опрашивает: таймер работает в самом виджете.

## Настройка хостинга

Docker-хостинг: сборка из `Dockerfile`, никаких pip-зависимостей. В панели переменных окружения задайте **обязательно токен и хотя бы одна переменная с ID групп**:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен от @BotFather; НЕ добавлять в GitHub |
| `CHAT_IDS` | ID нескольких групп через запятую: `-1001111111111,-1002222222222` |
| `CHAT_ID` | Альтернатива для одной группы: `-1001234567890` |

Дополнительные переменные:
- `WIDGET_API_BETA=1` (по умолчанию) — Telegram Bot API 10.4 beta, `https://api.telegram.org/beta/bot<TOKEN>/test/sendWidget`. Укажите `0`, если `sendWidget` уже работает в основном Bot API.
- `LAUNCH_AT=2026-11-18T22:00:00+03:00` — точное время завершения отсчёта; если пусто, ровно **10 суток от первой отправки**.
- `STATE_DIR=/data` — каталог для `announcement_state.json`, который **желательно закрепить как постоянный том** (volume). Без постоянного тома повторное развёртывание может потерять память о публикации.

## Права и запуск

1. Добавьте бота в группу администратором, разрешите отправлять медиа. **Право закреплять сообщения необязательно**: если оно есть, бот закрепит анонс, иначе просто отправит его.
2. Укажите `BOT_TOKEN` и `CHAT_ID` через секреты/переменные хостинга.
3. Запустите Docker-приложение. Бот проверит права, отправит виджет методом `sendWidget`, сохранит ID сообщения, вызовет `pinChatMessage`, только если разрешено закрепление.
4. Проверьте лог: `✅ анонс закреплён!` или `✅ анонс отправлен без закрепления`.

Для нескольких групп бот использует **один общий срок завершения** (10 суток после первого запуска), отправляет и закрепляет виджет **в каждой группе отдельно**. Ошибка в одной группе не препятствует остальным. Если позже добавите новый ID, сообщение появится только в новой группе. `CHAT_IDS` имеет приоритет над `CHAT_ID`.

При обычном перезапуске бот не отправляет ещё один пост, если сохранён файл состояния. Также он проверяет **последнее закреплённое сообщение**, чтобы избежать дубля, если файл состояния пропал. Если кто-то закрепил другое сообщение и файл потерян, повторная отправка всё ещё возможна — **постоянный том важен**.

## Ограничения

**Метод `sendWidget` документирован Telegram для Bot API 10.4 beta**. Для реальной отправки нужен доступ к нему и поддерживающий HTMLBubbles клиент Telegram. Если beta недоступна, бот **не отправит обычное текстовое сообщение вместо HTML** и завершится с ошибкой в логах. На старом клиенте может быть показана только подпись, без анимации.

**HTML-файл нельзя заменить обычным `sendMessage`: это другой тип медиа.** Анимация использует CSS, счётчик — JavaScript. Из-за ограничений некоторых клиентов оформление может выглядеть иначе, чем в обычном браузере.

В исходном коде нет токенов, секретов и платных зависимостей. Пользовательских команд у анонс-бота нет. Самостоятельно он не публикует сообщение спустя 10 дней — только меняет надпись в виджете.

Документация Telegram: [widget-sandbox / tgw-format](https://github.com/TelegramMessenger/widget-sandbox/blob/main/docs/tgw-format.md) и [profile v1](https://github.com/TelegramMessenger/widget-sandbox/blob/main/docs/profile-v1.md).

## 🧪 Проверка в личном чате

1. Откройте бота в Telegram и **нажмите Start / отправьте /start**, чтобы ему разрешили писать вам.
2. Узнайте свой числовой Telegram ID (например, через @userinfobot).
3. В переменных хостинга установите `PRIVATE_TEST_CHAT_ID=123456789` (замените на свой ID) и `WIDGET_API_BETA=0`.
4. Перезапустите хостинг. Бот отправит виджет **только в личный чат**, не затрагивая `CHAT_IDS`, без попытки закрепления.
5. Чтобы вернуться к группам, удалите переменную `PRIVATE_TEST_CHAT_ID` и перезапустите приложение.

Если Telegram вернёт `INPUT_MEDIA_WIDGET_NOT_ALLOWED` и в личном чате — отправка HTMLBubbles пока заблокирована для данного бота/режима API. Отправка обычного сообщения вместо виджета автоматически не производится.
